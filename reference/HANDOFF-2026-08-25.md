## The annual XBRL path — `vss xbrl --annual`, and the first fetched §5 input

**Commit `448a283`. Suite 1500, from 1471. Nothing existing was modified.**

`vss xbrl` fetched only the §4.2 quarter shape and carried **no cash-flow line
at all**, so Method C — which E28 made the engine — had nothing to read and
every US filer's fair value was reached by hand out of a 10-K. It now fetches
the cash-flow and balance-sheet facts §5 needs and **writes
`config/manual/<TICKER>.yaml`**, so §5 reads them through `vss manual`: the
same validation, the same **E21** gate, the same basis machinery every other
name gets.

**Origin `sec-xbrl`** — named that way and not `xbrl` because ESEF packages are
XBRL too (Eiffage files one) and a reader must be able to tell which registry a
figure came out of. **A figure's page reference IS its provenance:** the
us-gaap tag, the context period and the accession number.

**ANNUAL, not quarterly, and that is the point.** Filers stopped tagging
discrete fourth quarters when the SEC dropped the quarterly-data requirement in
2021, so the newest COMPLETE tagged quarter can lag the newest filing by
months. The entries land in the **`annual:` block (E15)**, keyed on the fiscal
year, and **E19's `as filed` branch** carries them. No new branch was written.
